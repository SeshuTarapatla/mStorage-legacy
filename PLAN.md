# mStorage — Flutter Migration Plan

## Overview

This document is the authoritative plan for migrating mStorage from a set of Python CLI scripts (compiled via Nuitka) to a single Flutter Windows desktop application. The goal is feature parity with the legacy toolchain — no new features — while eliminating loose binary dependencies and delivering a modern, maintainable codebase.

---

## Goals

| Goal | Details |
|------|---------|
| Language migration | Python → Dart/Flutter |
| Target platform | Windows desktop (only) |
| Eliminate RAR binary | Replace with AES-encrypted ZIP via `archive` Dart package |
| Eliminate loose ffmpeg.exe | Managed via `ffmpeg_kit_flutter` (see risk note below) |
| Legacy decode support | Must decode old RAR-inside-MP4 files encoded by legacy binaries |
| Build system | Replace Nuitka with `flutter build windows` |

---

## Scope (Strict)

**In scope:**
- Encode: video + optional poster/SRT → encoded MP4
- Decode: encoded MP4 → extract original files
- Player: launch Syncplay with selected video
- Legacy decode: handle old files (RAR-compressed archives inside MP4)

**Out of scope (future):**
- Multi-platform support (Android, macOS, Linux, iOS)
- Any new features beyond what the legacy binaries provide
- UI redesign beyond what's needed to replace the CLI interface

## Tech Stack

| Component | Choice | Rationale |
|-----------|--------|-----------|
| Framework | Flutter (Windows desktop) | Cross-platform foundation, good for future expansion |
| Language | Dart | Flutter's native language |
| Compression (new) | `archive` pub.dev package | Pure Dart ZIP with AES-256 encryption — no binary |
| Video generation | `ffmpeg_kit_flutter` ⚠️ | See critical risk note below |
| File picking | `file_picker` | Native Windows file dialogs, drag-and-drop |
| Legacy RAR extraction | Bundled `unrar.exe` asset | No pure Dart RAR reader exists; see legacy strategy |
| Build | `flutter build windows` | Replaces Nuitka, produces native MSIX/EXE |

## ⚠️ Critical Risk: ffmpeg on Windows Flutter

**Problem:** `ffmpeg_kit_flutter` (and its community fork `ffmpeg_kit_flutter_new`) does **not** officially support Windows desktop. The package targets Android, iOS, macOS, and Linux only.

**Resolution — two-track approach:**

1. **Attempt 1:** Try the community fork `ffmpeg_kit_flutter_new` at project start. If it gains Windows support by the time of implementation, use it.
2. **Fallback (likely path):** Bundle `ffmpeg.exe` as a Flutter asset inside the app package (`assets/bin/ffmpeg.exe`). Extract it to a temp directory on first run and invoke via `dart:io Process`. This is fundamentally different from the current approach (loose binary in `bin/`) — the binary is embedded in and distributed with the Flutter executable, invisible to the user.

This fallback still achieves the user-facing goal: no external binary dependencies, single-file distribution.

## Legacy Decode Strategy

Old files contain a **RAR archive** (not ZIP) after the `\nbreakpoint\n` marker, encrypted with a hardcoded password baked into the legacy Nuitka binary.

**Challenge:** There is no pure Dart RAR reader. The `archive` package does not support RAR format.

**Solution:** Bundle `unrar.exe` as a Flutter asset (Windows-free tool, ~400KB). This is used **only** for legacy file extraction. New files encoded by the Flutter app will use AES-encrypted ZIP and will not need unrar.

**Legacy decode flow:**
1. Read MP4, split on `\nbreakpoint\n` → write bytes after marker to a temp `.rar` file
2. Extract temp `unrar.exe` from Flutter assets to a temp directory (once per session)
3. Call `unrar.exe x -p<password> <file.rar> <output_dir>` via `dart:io Process`
4. Clean up temp files

**Password handling:** The legacy password was hardcoded in the Nuitka binary. The Flutter app will present a password input field for legacy decodes. The user provides it manually (since it's no longer baked in).

---

## New Encoding Format

New files encoded by the Flutter app will use the following structure:

```
[ mask video (MP4, generated by ffmpeg) ]
[ \nbreakpoint\n ]
[ AES-256 encrypted ZIP (via Dart `archive` package) ]
```

The ZIP contains:
- The source video file
- Optional: `.srt` subtitle file
- Optional: poster image

The breakpoint separator and outer MP4 container are **preserved** for format continuity. The only change is the archive inside: RAR → AES-encrypted ZIP.

## UI Design

Since this replaces 3 separate CLI scripts, the Flutter app will have a single window with **tab-based navigation**:

### Tab 1 — Encode
| Field | Type | Notes |
|-------|------|-------|
| Video file | File picker + drag-drop | Required |
| Title | Text input | Defaults to filename |
| Date | Date picker | Defaults to today |
| Time | Time picker | Defaults to 07:00:00 |
| Poster image | File picker | Optional |
| Subtitle (.srt) | File picker | Optional |
| Password | Password input | For ZIP encryption |
| Encode button | Button | Shows progress bar during encode |

### Tab 2 — Decode
| Field | Type | Notes |
|-------|------|-------|
| Encoded MP4 | File picker + drag-drop | Required |
| Password | Password input | Required; auto-detects legacy vs new format |
| Output folder | Folder picker | Defaults to same directory as input |
| Decode button | Button | Shows progress |

Auto-detection logic: read first 1MB, check if archive after breakpoint is a ZIP (`PK\x03\x04` magic bytes) or RAR (`Rar!` magic bytes), and route to the appropriate decoder.

### Tab 3 — Player
- Scans current directory and subdirectories for video files
- Lists found videos
- "Launch with Syncplay" button
- Checks for `SyncplayConsole.exe` in Program Files on startup; shows error if not found

## Phased Implementation Plan

### Phase 0 — Project Bootstrap
- [ ] `flutter create --platforms=windows mstorage_app` inside the repo
- [ ] Add dependencies to `pubspec.yaml`: `archive`, `file_picker`, `ffmpeg_kit_flutter_new` (or fallback plan), `path_provider`, `path`
- [ ] Add `assets/bin/` directory and register in `pubspec.yaml`
- [ ] Place `unrar.exe` and `ffmpeg.exe` (if needed) in `assets/bin/`
- [ ] Confirm `flutter build windows` produces a runnable EXE
- [ ] Delete `build.py` (Nuitka builder — no longer needed)

### Phase 1 — Core Format Layer (`core/`)
- [ ] Implement `mstorage_format.dart`: functions to split an MP4 on `\nbreakpoint\n` and to assemble mask + breakpoint + archive into an output file
- [ ] Implement `zip_service.dart`: AES-256 encrypted ZIP creation and extraction using `archive` package
- [ ] Implement `rar_service.dart`: extract bundled `unrar.exe` to temp dir, call via `Process.run`, handle exit codes and errors
- [ ] Implement auto-detection: inspect magic bytes after breakpoint to determine RAR vs ZIP
- [ ] Unit tests for format layer with small test fixtures

### Phase 2 — ffmpeg Integration (`core/ffmpeg/`)
- [ ] Try `ffmpeg_kit_flutter_new` on Windows — verify it compiles and can run a command
- [ ] If it works: implement `ffmpeg_service.dart` using the package API
- [ ] If it doesn't: implement `ffmpeg_service.dart` using bundled `ffmpeg.exe` via `Process.run`
- [ ] Implement mask video generation: 5-second video from poster image, `creation_time` metadata injection, 1920x1080 scale
- [ ] Implement fallback frame generation (blank black frame) when no poster is provided

### Phase 3 — Encoder Feature (`features/encoder/`)
- [ ] Implement `encoder_service.dart` orchestrating: mask generation → ZIP creation → file assembly
- [ ] Implement `encoder_screen.dart` with all input fields, file pickers, progress indicator
- [ ] Wire service to UI with async progress reporting
- [ ] Test: encode a sample video, verify output plays in VLC (mask) and decodes correctly

### Phase 4 — Decoder Feature (`features/decoder/`)
- [ ] Implement `decoder_service.dart` with new-format (ZIP) path and legacy-format (RAR) path
- [ ] Implement `decoder_screen.dart` with file picker, password field, output folder picker, progress indicator
- [ ] Auto-detection of format displayed to user ("Legacy RAR format detected" / "New ZIP format detected")
- [ ] Test: decode a legacy `.mp4` file encoded by the old binary; verify all files extracted correctly
- [ ] Test: decode a new `.mp4` file encoded by the Flutter app

### Phase 5 — Player Feature (`features/player/`)
- [ ] Implement `player_service.dart`: scan directories for video files, locate `SyncplayConsole.exe`, launch via `Process`
- [ ] Implement `player_screen.dart` with video list, single-click launch
- [ ] Handle Syncplay not installed: show actionable error with install link

### Phase 6 — Build & Distribution
- [ ] Configure `flutter build windows --release`
- [ ] Verify bundled assets (`unrar.exe`, optionally `ffmpeg.exe`) are included in the output
- [ ] Test the release build (not debug) end-to-end on a clean Windows machine
- [ ] Update `README.md` with new usage instructions
- [ ] Archive / remove legacy Python scripts (`encoder.py`, `decoder.py`, `player.py`, `build.py`) — keep in git history

## Risks & Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `ffmpeg_kit_flutter` has no Windows support | High | Fallback: bundle `ffmpeg.exe` as asset (Phase 2) |
| `archive` package AES-ZIP not compatible with WinRAR/7-Zip | Low | Test interoperability in Phase 1 |
| `unrar.exe` flagged by Windows Defender | Medium | Use official UnRAR from rarlab.com; document this for users |
| Legacy password unknown to new app | Known | User enters password manually in Decode tab |
| Large video files causing UI freeze | Medium | All encode/decode operations run in Dart isolates |
